## What is retained

The 63 plot columns contain current OHLCV, epoch-ms clocks/index, explicit state flags and four input frames: INITIAL, UPDATE1, UPDATE2, CLOSE. COLUMN-SCHEMA-v1.json defines all indices and flag bits. The four fixed varip float buffers exist solely to preserve early observations while the operator opens the export dialog. They do not simulate a feed. The initial frame is reset by BAR_TIME changing, **not** by isnew: the first live update of the same timestamp must not erase an initial historical-looking pass.

INITIAL is the first observed last-bar evaluation for that timestamp. UPDATE1/UPDATE2 are the first two strictly later unconfirmed realtime evaluations. CLOSE records the first realtime+confirmed evaluation. Frames hold their own OHLCV/time/flags/ordinal; a snapshot embedded in a confirmed CSV row remains a realtime/startup observation, not historical data. STAGES_PRESENT=15 means all four buffers are populated, not automatic context acceptance.

IS_ATTACH_BAR=1 identifies the last bar first seen when this draft was added. A later bar's sequence is useful separately but cannot certify fresh-script startup. INITIAL may have historical/confirmed flags before realtime data arrives. Preserve those flags exactly. Physical-open evidence comes from the native current-bar/countdown view and capture provenance, not from rewriting isconfirmed or from guessing from wall-clock time. Record any delayed-feed offset explicitly.

## Capture sequence (each source independently)

1. Before Add: record the DXY current bar, timestamp/countdown, market/feed status and existing chart settings. Start a new local attempt/session ID. Add the exact unsaved primary source while a physical bar is open. Identify target T by its CURRENT_BAR_TIME_MS and CURRENT_BAR_INDEX. Capture the initial view promptly; the retained INITIAL fields protect against dialog latency. The strict startup case requires IS_ATTACH_BAR=1, INITIAL_VOLUME missing and its flags bit128=1, plus evidence that T was physically open. Do not invent that prerequisite if volume is already zero.
2. **INITIAL_OPEN**: screenshot chart/countdown and Data Window, then export original raw-initial-open-v1.csv with indicator values included. Record capture/export UTC times and all raw CURRENT/INITIAL strings for T. An export may finish after another tick: label the export's CURRENT row by its actual flags/ordinal, while INITIAL_* remains the retained startup observation. Never relabel a later current row as the initial evaluation.
3. **UPDATE1**: let the native feed execute again on the SAME T, without refresh/re-add/source change/timeframe change. Observe UPDATE1 populated, realtime=1 and confirmed=0 from its stored FLAGS. Export raw-update1-v1.csv and screenshot. Preserve the actual OHLCV; distinguish missing from genuine volume zero. UPDATE1_EXECUTION must exceed INITIAL_EXECUTION.
4. **UPDATE2**: wait for a second genuine, strictly later unconfirmed realtime execution on the SAME T. Capture UPDATE2 fields, export raw-update2-v1.csv and screenshot. Require UPDATE2_EXECUTION>UPDATE1_EXECUTION. Do not count a second download, clock countdown, reload or duplicate view as an update. Unchanged prices may be valid feed executions; the retained ordinal/clock and provenance must demonstrate distinct native evaluations.
5. **BAR_CLOSE**: wait for the native closing evaluation, not merely time_close passing. Capture/export raw-bar-close-v1.csv immediately. Select T (not a newly opened bar) and require populated CLOSE_* with realtime=1, confirmed=1, history=0, and CLOSE_EXECUTION>UPDATE2_EXECUTION. If a new bar has opened, use the committed T row without refreshing. Never replace it with a later recalculated historical row. A screenshot/countdown plus an authenticated native CSV carrying the close frame is required. If native export loses varip frames or excludes the open/close row, retain what exists and mark the affected facet CONTEXT-UNMET; rounded Data Window numbers alone earn no exact-value credit.
6. Add the renamed source through the same allowed unsaved-draft flow. It needs its OWN initial/two-update/close attempt; do not reuse primary frames. It may be co-hosted if both fit the account/chart. Record source/study bindings for duplicate CSV headers by ordinal and title; never key only by label. Adding another study can recompute a script: if a primary INITIAL_CLOCK_MS changes, buffers vanish, or its ordinal resets, discard the combined sequence credit and start a separate attempt. Comparing a later fresh control with an earlier primary is context-bounded: only exact same-context overlapping inputs are comparable. Different startup clocks/epochs are not evidence of a naming effect, and control evidence never fills a missing primary event.

Keep each original CSV byte-for-byte, including missing strings, scientific notation, headers and open rows; hash it and record its source/study/context binding. Do not stitch realtime rows into one OHLCV historical feed or overwrite prior exports. Store original screenshots and snapshots with their event/export timestamps.

After capture, make these DERIVED local artifacts, with source-CSV hash and row/column ordinals:

- historical-prefix-v1.csv: only independently physically confirmed preceding bars, excluding T at every phase. Keep raw strings. Record cutoff and first/last index. Script isconfirmed=1 alone does not promote the initially open T to this set.
- realtime-events-v1.jsonl: exactly INITIAL_OPEN, UPDATE1, UPDATE2 observations for T, extracted from their retained fields. Decode each frame's own FLAGS, not the containing row's CURRENT flags. Never assign OHLCV from a later export to an earlier event. Keep input rows with identical timestamps as separate events ordered by EXECUTION/CLOCK_MS and capture provenance.
- confirmed-close-v1.json: only the actual CLOSE frame for T, with its live closing flags and provenance. Keep it separate from the historical prefix and startup/update rows.
- column-bindings-v1.json: every plot column's CSV ordinal, canonical label, indicator/study role and executed source hash. Preserve ambiguous/duplicate headers rather than silently merging them.

All four stored frames must share T and BAR_INDEX. Verify that earlier snapshot fingerprints remain identical in later exports. If a script/chart reload occurs, start a NEW session; never concatenate sessions. Record missing-volume historical prefix, initial missing volume, and any subsequent native volume=0 recovery as separate facets. A complete sequence with no zero recovery does not settle the older missing-prefix→zero-feed case. No synthetic nans/zeros or arithmetic expectations may replace observed strings.
